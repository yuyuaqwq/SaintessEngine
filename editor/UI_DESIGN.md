# 框架编辑器 UI 设计稿（v2 · 工作室）

> 2026-09-11 立。鱼鱼反馈「现在的 UI 太敷衍」→ 本文是重新设计的方案。
> 约束不变：**零依赖**（单页 HTML + 原生 JS + Python stdlib http.server）、零构建、只绑 127.0.0.1。
> 后端 API **一行不改**（编辑器前端是纯消费方）。

| # | 问题 | 证据 |
|---|---|---|
| 1 | **编辑器自己的样式只有 53 行** | `app.css` 53 行，套用从游戏编辑器搬来的 `style.css` 变量 |

## 1. 设计目标（三条）

| 目标 | 含义 | 验收 |
|---|---|---|
| **A. 专业工作台质感** | 像 IDE/专业工具，不像 demo | 有完整设计系统；控件非默认外观；层次分明 |
| **B. 高频操作零鼠标** | 配置内容要快 | Ctrl+K 跳条目、Ctrl+S 保存、↑↓ 选择、/ 搜索 |
| **C. 状态透明** | 改了什么、哪条有问题、能不能存 | 变更预览 + 状态栏 + 列表问题标记 + 未保存守卫 |

**非目标**（明确不做）：主题切换（保持暗色单一）、多语言、插件化 UI、移动端适配、
拖拽排序（内容顺序由数据决定）、富文本。

## 3. 设计系统（v2 全部 token）

### 3.1 主题系统（★ 可换肤：预设 + 自定义）

配色**不是写死在 CSS 里**，而是运行时由 `web/theme.js` 写入 `<html style="--bg-0:…">`。
`app.css` 的 `:root` 只保留一套「深色默认（猫猫夜）」作为**无 JS 兜底**。

```
改配色 → 改 editor/web/theme.js 的 MODE_BASE / PRESETS（不要改 app.css 的 :root）
```

**两条轴**：模式（深色 / 浅色 / 跟随系统） × 配色来源（预设 / 自定义）。

**7 个预设**（每个自带签名强调色）：

| 预设 | 模式 | 基调 | 强调色 |
|---|---|---|---|
| 猫猫夜 | 深 | 低饱和柔紫（默认） | `#cba6f7` |
| 极夜 | 深 | 冷蓝深空 | `#7aa2f7` |
| 幽林 | 深 | 墨绿沉静 | `#86d3a4` |
| 暮色 | 深 | 暖褐琥珀 | `#e8a87c` |
| 白昼 | 浅 | 冷白柔紫（默认） | `#8839ef` |
| 纸白 | 浅 | 暖白赭石 | `#b0641f` |
| 晴日 | 浅 | 米黄靛蓝 | `#268bd2` |

**自定义**：14 个可取色的 token（背景 5 档 / 边框 2 档 / 文字 3 档 / 强调色 / 成功·警告·错误），
改任意一项即切到该模式的「自定义」配色；派生值（hover 色、半透明底、按钮文字色）自动算出。

**派生规则**（保证换任何色都不糊）：

| 派生 token | 规则 |
|---|---|
| `--accent-hi` | 深色主题混白 18% / 浅色主题混黑 14% |
| `--accent-dim` `--accent-soft` | 强调色 16% / 36% 透明度 |
| `--on-accent` `--on-err` `--on-ok` | 按底色**亮度**自动取深字或白字（`readableOn`） |
| `--diff-del` `--diff-add` | 按模式给对比度足够的红/绿 |

**实现要点**：
1. `theme.js` 必须在 `<head>` **同步加载** —— 首屏绘制前把变量写进去，否则会闪一下默认色
2. 切换动画：只在切换瞬间挂 `html.theming`（140ms 颜色过渡），不常驻
   —— 避免覆盖组件自己的 transition，也让 `getComputedStyle` 能立刻取到终值
3. 后台标签页 `setTimeout` 会被节流（过渡类摘不掉）→ `visibilitychange` 兜底清理
4. 设置存 `localStorage`（`fe.preset.dark` / `fe.preset.light` / `fe.accent` / `fe.custom` …）
   —— **本机浏览器生效，换设备不跟随**（界面上有明示）

**色板语义**（每套主题都遵守）：5 级 elevation（`--bg-0` 最深 → `--bg-4` 最亮）
+ 4 级文字（`--fg-0` 主 → `--fg-3` 最弱）+ 语义 3 色 + 内容 kind 8 色。

## 3.5 表单排版（网格化，v2.1）

**问题（实测）**：56 个字段各自占满一行，宽 927px / 高 67~105px，而控件本体只有 28px 高
—— 像 `lv` 一个数字框独占 94px，空间利用率约 30%。

**做法**：`.schema-form` 与 `fieldset.grp` 改为**网格自动排布**
（`repeat(auto-fill, minmax(200px,1fr))`），配合 `:has()` 按控件类型决定跨列：

| 选择器 | 效果 |
|---|---|
| `.field:has(textarea)` | 文本域 → 占满整行 |
| `.field:has(.array-rows)` `.field:has(.kv-row)` | 数组/键值对编辑器 → 占满整行 |
| `.field:has(details.extra)` | 额外字段折叠块 → 占满整行 |
| `.field:has(fieldset.grp)` | **复合字段（anyOf/嵌套分组表单）→ 占满整行** |
| 其余（input / select） | 一格，自动 2~4 个一行 |

**实测效果**：排布行数 **56 → 19 行**，表单内容高 **5279 → 1612 px（-69%）**，
单字段高 42~198px，每行稳定 4 个；零截断、零溢出、零真重叠。

**约束**：`schema_form.js` 一行未改 —— 全靠 CSS 选择器适配它的既有 class 契约。
帮助文字（`.help`）在窄格会被 clamp 到 2 行，由 `app.js` 渲染后补 `title` 提示兜底。

## 3.7 机制动作挂接（E4）★

**问题**：声明表里的 `action` 是**自由字符串**（schema 明写「取值由内容侧声明决定」）。
写的人要么翻代码、要么凭记忆填；填错了**没有任何提示** —— 引擎到点查不到执行器就静默跳过
（「配了不生效」这类最难查的故障）。

**做法：从实现反推，而不是另建声明表。**

```
tools/export_actions.py    AST 扫源码 → 动作清单（引擎内置 + 包内）
  ├─ 装饰器        @register_action("name")          → 动作名
  ├─ docstring                                       → 说明（首段）
  └─ 函数体消费点  params.get("k") / params["k"]     → 参数名
                    ├─ params["k"]           → 必填
                    ├─ params.get("k", 0.25) → 类型 float + 默认 0.25
                    ├─ params.get("k", "s")  → 类型 string
                    └─ 默认值非字面量         → 标「运行期决定」
     过滤：`_owner` 等装配器注入键不进配置表单
```

**为什么不用「引擎里加注册表」**（设计稿原建议）：① 要改引擎核心（需审批）
② 声明与实现可能漂移。**从消费点反推则天然与实现一致**，且引擎零改动。

**UI 落点**（`passive_proc` 等含 `action` 字段的域）：

| 元素 | 说明 |
|---|---|
| 动作名字段 | 挂 `<datalist>` **联想**（不用替换元素 → schema_form.js 的事件链一行不动） |
| 来源标签 | 「框架内置」/「本包动作」+ 文件:行号（点得着、可核对） |
| 说明 | 动作 docstring 首段 |
| **参数区** | 每个参数一行：键名 + **输入框** + 类型；必填标 `*` |
| 参数已在 schema 里 | 不给输入框，改给「↗ 见上方字段」按钮（点击滚动 + 高亮）—— 避免两处重复编辑 |
| 找不到动作 | 红框提示「未找到动作 x —— 检查拼写，或确认它已在代码里注册」 |

**关键坑（实测踩到）**：动作参数**多数不在 schema 里**，schema_form 渲染不到它们。
若参数区只「列出名字」，用户填的值就成了**看不见的幽灵数据**。
→ 因此参数区给的是**真输入框**（直接写 `entryData`），并配焦点保护
（动作名 input 只在**名字真的变了**时才重渲染参数区，否则每次按键重建 DOM 会打断输入）。

**验收**（全部实跑）：
- `tools/export_actions.py --selfcheck` 11 断言；`tests/test_editor_actions.py` **33 断言**
- 浏览器实测：联想 10 项、参数编辑（焦点不丢 + 类型收敛 `"3"`→`3`）、
  `apply` 的 15 参数中 `mode`（在 schema）自动转跳转按钮、保存落盘
- **端到端**：`games/my_game/content/mech/actions.py` 的 `demo_echo` 真跑
  → `💥 受害者 受到 100 点伤害` + `⚡ 回响反击·测试：100 点伤害！`（配的参数确实生效）；
  `chance=0` → 无行为（零默认值铁律）

## 4. 交互设计

### 4.1 键盘（工作流核心）

| 键 | 动作 |
|---|---|
| `Ctrl/⌘+K` | 命令面板（跳条目 + 执行动作） |
| `Ctrl/⌘+S` | 保存当前条目 |
| `/` | 聚焦搜索框 |
| `↑` `↓` | 列表内移动（自动打开） |
| `Alt+↑/↓` | 切换域 |
| `Ctrl+Enter` | 试跑当前条目 |
| `Esc` | 关面板 / 关外观 / 取消搜索 / 关抽屉 |

### 4.2 命令面板（新增，最大效率增益）

一个输入框，两类结果合并模糊搜索：

```
条目    ⚔ 火焰斩            skills · 物理
        🐺 石炉守卫          monsters
动作    ✓ 全包校验
        ＋ 新建条目
        ⚙ 打开包设置
        ⚔ 试跑当前条目
```

### 4.3 变更预览（新增）

编辑器第三档 `变更`：客户端 diff（加载时快照 vs 当前值），按字段列出
`路径 | 旧值 | 新值`，未改动的字段折叠。**保存前先看改了什么**——现在完全没有。

### 4.4 状态透明

| 位置 | 显示 |
|---|---|
| 列表行 | 悬停显 key；有问题显左侧红条 + ⚠；未保存显右侧黄点 |
| 编辑器头 | kind chip + key + `● 未保存` |
| 动作栏 | 保存按钮在无改动时 `disabled`；有改动时 accent 高亮 |
| 状态栏 | 包路径 · 未保存计数 · 待修计数 · 引擎版本要求 |
| 域栏 | 每个域角标显条目数；有问题时角标转红 |

### 4.5 校验问题定位

校验失败（422）→ 顶部 `.issues` 条：
```
⚠ 2 个字段有问题         [定位到第一个 ▸]
  · $.kind  必须是枚举值之一
  · $.power 类型应为 number
```
点「定位」→ 切到表单档 + 滚动到该字段 + 高亮（复用 `SchemaForm.markErrors`）。
