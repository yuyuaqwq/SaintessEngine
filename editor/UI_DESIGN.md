## 8. 实施记录：字段分组 + E5 导出分发（2026-09-11 第三轮）

鱼鱼口径：「字段可以适当按分类分组吧，然后你可以继续做收尾」。

### 8.1 字段分组（`editor/glossary.py` 的 `GROUPS`）

56 个技能字段平铺着扫太累。按**语义**分块，每块一个可折叠卡片：

```
技能：📌基础(5) · ⚡消耗与节奏(6) · 💥伤害与命中(10) · 🩹治疗与减伤(5)
     · 🌀状态与机制(13) · 🎯仇恨与嘲讽(3) · 🔗条件与被动(2)        = 56 ✓
声明表：📌基础与归属(5) · 🔢叠层与面板(4) · ⏳周期结算(1) · 🧊冷却与开局(4)
       · 🛡濒死保护(4) · 🌀控制与渠道(3)                           = 21 ✓
被动声明：⚡事件钩子(4) · 🗂静态域(2) · 🔍判据与条件(5) · 📦资源与计数(8) · 🎛动作参数(5)
```

实现要点：
- `schema_form.js` 加**可选** `groups` 选项（不传 = 旧平铺行为，一行没改老路径）；
  每组渲染成一个 `fieldset.grp.cat`，**沿用既有 `.grp` 样式**（内层网格、整行占位都白拿）
- 未列进任何组的字段 → 自动进「未分组」组（**不丢字段**，漏了看得见）；门禁断言
  「155 个顶层字段一个不漏、一个不重、无幽灵名」
- 折叠状态由调用方记（`S.collapsed`，key = `域#组id`），**重渲染 / 切域不丢**；
  命令面板给「折叠全部分组 / 展开全部分组」
- 点「定位」跳到折叠组里的字段时**自动展开那一组**（否则等于把人带到看不见的地方）

### 8.2 新手感修掉的三个坑（都是实跑踩的）

| 坑 | 现象 | 修法 |
|---|---|---|
| 旧表单残留 | 切域后 `#formHost` 还留着上一条目的表单（隐藏），`querySelector('.field[data-path=…]')` 命中幽灵节点 | `closeEntry()` 里清空 `formHost`/`diffHost` |
| 草稿带幽灵键 | 新建任何域都塞 `{name,kind,lv,desc}` —— 声明表域没有这三个字段，渲染成「其他字段」 | 初始值**按 schema 给**（域里没有就不塞） |
| 导入挂死 | `/api/packages/import` 前 `_mutate` 先调了 `_body()` 把请求体读空 → `_raw_body()` 永远等不到数据，HTTP 挂到客户端超时 | 裸字节流端点放在 `_body()` **之前**处理 |

### 8.3 E5 导出 / 分发（`editor/dist.py`）

导出物 = **解压即用的游戏包**（`game.json` 在 zip 根）+ 两个附赠件：

```
my_game-20260911-1952.zip
  game.json / content/…          ← 包本体（第三方解压即用）
  DIST_README.md                 ← 引擎要求 + 怎么跑 + 域清单（表格）
  DIST_smoke.py                  ← 一条命令自检：python DIST_smoke.py
  [zip comment] 机读元数据       ← 格式/版本/id/导出时引擎版本/条目数（不落文件）
```

`DIST_smoke.py` 是「分发」这个词的硬证据：它在**干净目录**里装包 → 起一场战斗 →
打印日志，跑通输出 `[√] 跑通：普攻造成 N 点伤害`。若包自身没装配「最小可打」三件套，
脚本会**临时补上并如实打印**（不改包文件）。

导入四道闸（默认拒绝，不静默降级）：

```
① zip slip   绝对路径 / .. / 符号链接 → 整包拒绝，一个都不写盘
② zip bomb   条目数 > 2000 或解压 > 64MB → 拒绝
③ 清单合规   game.json 合法 JSON + id 合法（同一正则）
④ 引擎版本   engine 要求不满足 → 422 拒绝；force=1 才放行并留警告
冲突：同 id → 409（overwrite=1 才覆盖）；失败导入不留垃圾（先在临时目录验完再搬）
兼容：根布局 与 GitHub 风格单层目录（自动剥壳）都吃
```

界面：包菜单 / 设置页 →「📦 导出 zip」「⬆ 导入 zip…」，命令面板同样两项。

## 9. 实施记录：控件形态 + 联想（细节扫一遍，2026-09-11 第四轮）

鱼鱼口径：「还有很多可以优化的点，你全部扫一遍，比如描述你是可以用比较大的框，
kind之类的是可以用列表框的吧？这种细节也优化一下」。

### 9.1 控件形态：按**字段语义**指派控件（不是全靠文本框）

| 字段语义 | 控件 | 覆盖的字段 |
|---|---|---|
| 长文案 | **多行大框**（自适应长高，上限 320px） | `desc` · `flavor` · `heal_formula` · `food_effect` |
| 一行一条的字符串数组 | **多行框**（一行一条 · 空行忽略 · 条数读数） | `exprs` · `maps` |
| 0~1 的比值 | **数字 + 滑杆联动**（带百分比读数） | `chance` · `mech_chance` · `lifesteal` · `guard_hp_pct` · `heal_pct` · `overload_heal_pct` |
| 枚举数组 | **多选标签 chips**（原先掉进 JSON 兜底） | `qualities` |
| 对象型字段 | **键值行 + 键联想**（原先 `channels`/`debuff_scale` 是裸 JSON） | `channels` · `stat_scale` · `debuff_scale` · `judge` · `effect_data` |

实现：`schema_form.js` 新增**可选** `widget/suggest/suggestKey` 三个回调（不传 = 旧行为），
或 schema 自带 `x-widget`；另有通用启发（`maxLength ≥ 120` 的长字符串自动给大框）。
枚举数组→chips 是**内置**改进（原先无论谁调用都是 JSON 兜底）。

### 9.2 联想：**全部来自包自己的数据**（框架零游戏词汇）

`editor/hints.py`（新增）扫包内已有条目，产出三类候选：

```
refs   {域: [真 key]}          跨域引用候选（技能 / 物品 / 职业 / 效果 key）
values {域: {字段: [已有取值]}}  自由串候选（kind / element / effect / mech …）
keys   {域: {字段: [用过的键]}}  对象字段的键（channels 的时机名 / stat_scale 的面板键 …）
```

为什么不用枚举写死：`tests/test_no_game_vocabulary.py` 明令框架层不得出现游戏词汇 ——
「技能的种类有：物理/魔法」写进 schema 就是把某个游戏的知识写进框架。用包内数据做候选，
第三方做什么游戏，候选就跟着变；而且候选**一定真实存在**（拼错当场避免，引擎那边是静默空放）。

`kind` 的处理正是这条：**输入框 + 联想（datalist）**而不是死 `<select>` ——
框架里 `kind` 的取值由内容侧声明，枚举不出来；能选已有值、也能敲新值才是对的。
真枚举（`aoe` / `target` / `role` / `trigger` / `quality`）**本来就是下拉**。

细节：`name` / `id` / `tag` 是身份字段，**不给联想**（候选只会诱导重名）。

### 9.3 顺带扫出来的其它细节

| 项 | 改动 |
|---|---|
| 列表看不清 | 每行加 `Lv` 标记 + 悬浮显示「Lv · 描述摘要」 |
| 搜索 | 命中处 `<mark>` 高亮（与命令面板一致） |
| 造相似条目 | **复制条目**（`⧉ 复制` 按钮 / 命令面板 / **Ctrl+D**），名字自动加「副本」 |
| 折叠 | 编辑器头加「⤴ 展开 / ⤵ 折叠」按钮；**Ctrl+\** 一键全折叠/全展开 |
| 长表单定位 | 分组标题**吸顶**（滚到中段也知道自己在哪一组） |
| 身份字段乱联想 | `name`/`id`/`tag` 不联想 |
| `channels` / `debuff_scale` 是裸 JSON | 按 wiki 事实补 schema（值形态 number \| {gain,when,per_dt}；每层系数 number）→ 变成键值编辑器 |

### 9.4 扫描结果：一个**设计问题**要鱼鱼定

`schema/monster.schema.json` 里有 5 个 `$defs`，但**只有 `monster_skill`（21 字段）有入口**
（域注册表 `primary: monster_skill`）。另一个有字段的 def 是 **`hidden_monster`（12 字段：
id / role / lv_off / skills / drops / gold_mult / cond / chance / tag / flavor / maps）——
编辑器没有域指向它**（其余 def 都是 0 字段的整表壳）。

建议：要么给它开一个域（编辑器里就能配「怪物的技能池 / 掉落 / 出现地图」），
要么从框架模板 schema 里删掉（它是**奥兰迪亚的叫法**，直接拿来当框架域会污染中立性 ——
命名得先定，如 `monster_spawn` / `monster_template`）。**待拍板，未擅自加。**

## 10. 实施记录：`maps` 域 + 拓扑视图（2026-09-12 第五轮）

框架路线图 #6「地图形状 → 引擎」的编辑器侧验收项是 **「配 `maps` 域 → 编辑器能画地图」**。
引擎侧（`ext_world.space`）与内容侧（参考实现的 `core/maps.py`）同批完成，见
`docs/engine-wiki/reference/space.md` 与游戏仓 `docs/archive/REFACTOR_v183_space_shape.md`。

### 10.1 数据形态：一条 = 一张图

```json
{ "sample_town": {
    "name": "示例镇", "topology": "star",
    "roles": { "hub": "hub", "through": "through", "exit": "exit" },
    "nodes": [ {"id": "plaza", "name": "中央广场", "role": "hub"}, … ],
    "links": { }, "root": "", "gate": "" } }
```

* 节点表**顺序有意义**（链状/星形的「深度」= 声明序，首节点 = 入口）—— 表单里不排序、不改写
* `links` 一给就用它（显式连通表）；`topology` 与 `links` 同时给 → 视图里**明着警告**
  「连通表优先，拓扑名不参与派生」，不静默选一个
* schema **零 enum**（角色取值由内容侧定，框架不设分类）—— 这是中立性门禁的红线

### 10.2 关键决定：派生只有一份（编辑器不重写引擎）

`editor/space_view.py` 直接 import `ext_world.space` 算视图，前端**只负责画**。
这破了 `packages.py` 里「编辑器主进程不 import 引擎」的纪律 —— 理由写在 `space_view.py` 开头：
那条纪律针对的是**会挂 hook / 改全局状态**的战斗域，而 `space` 是**纯计算模块**
（零挂载、零副作用，与 `version` 同性质）。

代价换来的东西是硬的：**编辑器里看到的图和游戏里跑的是同一段代码**。
若在前端用 JS 重写一遍邻接/深度/出入口，两处迟早漂移，而且漂移时**没人会发现**
（编辑器画得好看，游戏里走不通）。

### 10.3 前端：第四档「拓扑」（仅 `maps` 域出现）

| 部分 | 做法 |
|---|---|
| 模式档 | `#modeSwitch` 加 `data-mode="graph"`（🗺 拓扑）；**只在 maps 域显示**，切到别的域自动收回 |
| 布局 | `graphLayout(view)` **纯函数**（`##GRAPH_LAYOUT_BEGIN/END##` 标记供 Node 单测抠出真跑）：x = depth 分列、同列按数据顺序排开、边按目标方位选出口侧（右/左/上下） |
| 绘制 | 单张 SVG：节点框 + 角色配色 + 有向箭头；`▶` 标入口、外环标出入口 |
| **审计上图** | 悬空边 → 红虚线 + 右侧补「虚影节点」（`?`）；不对称边 → 琥珀虚线；不可达 / 孤立 → 节点置灰。图例 5 项 + 摘要条（形状 / 节点数 / 边数 / 入口 / 出入口 / `✓ 结构检查通过` 或 `⚠ 结构问题：悬空边 N / 不对称 N / 不可达 N / 孤立 N`） |
| 不算 | 图是**按磁盘数据算的**；改完先保存再点「↻ 重新计算」（保存会让缓存失效 → 重新拉） |
| 画不出时 | 空节点 / `topology=mesh` 无 `links` / 未知形状名 → 居中显示**引擎给的中文原因** + 重算按钮，不白屏 |
