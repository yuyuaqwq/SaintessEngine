# 任务账本形状（账本 / 目标类型注册表 / 单条外壳）

> 模块：`ext_quest.quest`（**扩展包** —— 2026-09-23 起从引擎迁出，见 `extends/ext_quest/`） —— `QuestLog`（账本状态机）+ `Objectives` / `Objective` /
> `parse_needs`（目标类型注册表 + 进度折叠 + 行文骨架）+ `Quest`（单条只读外壳）。
> 一句话：**一份跨会话持久的多 lane 账本 + 一张有序的目标类型表**；
> 字段名、状态词、目标类型词、需求数口径、行文模板全部由内容侧给，引擎只认**结构字段名**与**注入口**。

## 为什么有它

参考实现里，一个任务系统被写成了三套状态机（主线一条链 / 支线多条 / 每日多条）
× 三份目标行渲染（接取单行 / 交付多行 / 面板进度行）× 一张硬编码的目标类型词表：

| # | 重复 | 现状 |
|---|---|---|
| 1 | **账本状态词** | 主线只用未接取/进行中/可交付（完成写进一个列表）；支线有终态；每日用整格计数 |
| 2 | **目标行渲染** | 接取通知单行首命中 / 交付面板多行全出 / 任务面板只有四型 |
| 3 | **需求数提取** | 「数量修饰 or 基础数」与「只看基础数」两种写法并存 |
| 4 | **需求数**与**进度键** | 击杀型记目标名、聚合型记固定键、使用型记类型名 —— 三套键口径 |

把「哪个字段叫当前任务 / 哪个词算完成 / 哪些目标类型存在 / 数怎么数 / 行怎么写」
这些**取值**剥掉，剩下的就是本模块的三件形状。

## 用法

```python
from ext_quest.quest import Objective, Objectives, Quest, QuestLog, parse_needs

# ① 注入面（引擎零默认取值：字段名 / 状态词 / 子账本形态都由内容侧给）
fields = {"current": <字段名>, "status": <字段名>, "progress": <字段名>,
          "archive": <字段名>, "lanes": <默认子账本名>}
states = {"todo": <未开始词>, "live": <进行中词>, "ended": <终态词>}
lanes  = ((<子账本名>, {"progress": dict}), (<整格计数子账本名>, {"progress": int}))

log = QuestLog(db.get_quests(...), fields=fields, states=states, lanes=lanes)   # O(1)
log.current; log.status; log.progress; log.done; log.lane(<名>); log.entry(<名>, <键>)
log.status_of(<名>, <键>); log.is_open(<名>, <键>)

# ② 状态迁移一律返回**新 mapping**（不改原 raw），落库由调用方自己做
raw = db.get_quests(...)
raw = log.deliver(lane=None, next_of=lambda cur: <下一环 id>).snapshot()
db.save_quests(..., raw)

# ③ 目标类型注册表：声明序 = 判定序 = 展示序
objs = Objectives(
    Objective(<类型名>, match=<fn(value, event)>, need=<fn(obj, engine)>,
              fold=<fn(obj, progress, event)>, text=<fn(obj, progress, ctx)>,
              multi=False, modifiers=(<修饰键名>, ...)),
    unknown=<未注册键策略>,        # 缺省 = 返回 None（不出行）
    need_of=<需求数口径>,          # 类型没自带 need 回调时用
)
objs.keys(); objs.parts(obj); objs.hits(obj, event)
objs.fold(obj, progress, event)            # → 补丁（不就地改）
objs.satisfied(obj, progress); objs.complete(obj)
objs.lines(obj, progress=..., state=..., text_of=<各出口自己的模板>)
parse_needs(obj, need_of=..., modifiers=(...))
```

## 引擎认什么（契约字段名）

引擎把调用方的原始 mapping **原样持有** —— 不归一、不拷贝、不补默认值，只按下列名字读：

| 层 | 角色键（**字段名**） | 边界（有意保留的口径） |
|---|---|---|
| 账本 | `current` / `status` / `progress` / `archive` / `lanes` | 缺失 → `None` / 未开始词 / `{}` / `[]` / 未声明；`raw` 与嵌套对象都是**原对象** |
| 条目 | 由调用方给的键（**不透明字符串**，名字即可、无需 id） | `entry` 缺失 → `None`；引擎不解析、不归一、不匹配源侧 id |
| 目标 | 内容侧注册的**类型键** + 内容侧声明的**修饰键** | 修饰键不单独出行；未注册非修饰键交给 `unknown` 策略 |
| 进度 | `{进度键: 值}` 或**整格计数** int | 进度键由内容侧 `fold` 决定，引擎只搬运、不解释 |
| 事件 | 任意 | 引擎一个字段都不读，整体透传给 `match` / `fold` |

> ⚠️ **命名口径（与设计稿的唯一差别）**：设计稿把账本角色键写成
> `current`/`status`/`progress`/`done`/`lanes`、状态角色键写成 `open`/`running`/`ready`/`closed`；
> 但 `done` / `open` / `closed` / `running` / `ready` **本身就是取值词**，引擎源码的字符串常量里
> 出现即触「零取值词」门禁。因此角色键改用同义的引擎词：`archive` / `todo` / `live` / `ended`
> （`ready` 那一档引擎根本不读 —— 它只影响内容侧的展示，不影响账本迁移）。
> **属性名照旧叫 `done`**（属性名不是字符串常量）；注入面的**语义一字未变**。

## 12 条口径分歧（**故意不统一**）

| # | 分歧 | 引擎怎么表达 |
|---|---|---|
| ① | 主线无终结状态 | 主 lane 交付 → `archive` 追加 + `status` 回未开始词；子账本交付 → 条目写终态一格 |
| ② | 三份目标行渲染不合并 | `lines()` 只出骨架（复合**全出**，行序 = 目标键序）；行文由各出口的 `text_of` 给 |
| ③ | 进度容器 mapping ∪ int | 子账本声明里带进度形态；清空分别写 `{}` / `0`；判定分别按值取键 / 整格比数 |
| ④ | 需求数两种口径 | `Objective.need` 回调优先，其次注入的 `need_of`；`parse_needs` 默认「首个正整数修饰键，退 1」 |
| ⑤ | 未注册目标类型 | `unknown(key, value)` 注入；**默认返回 `None`（不出行）** |
| ⑥ | 「缺失」≠「字面 null」 | `Quest.next` 两者都 `None`；裁决交给 `deliver(next_of=...)` 的内容回调 |
| ⑦ | 进度键口径 | `fold` 的补丁键原样写出；历史聚合兼容留在内容侧 |
| ⑧ | 三个门槛失败语义不同 | 引擎无过滤 API、无门槛字段（隐藏线 vs 明面门槛是内容侧信息设计） |
| ⑨ | 「不进列表」≠「面板不可见」 | 引擎对条目**零过滤**（带任何标记都能读到） |
| ⑩ | 每日任务键 = 名字 | 条目键是不透明字符串（中文/空格照原样），引擎不做 id 归一 |
| ⑪ | 跨天清理用系统钟 | 引擎**一个钟都不读**（无时钟注入口、`snapshot()` 只有原字段） |
| ⑫ | 行序 = 信息序 | `lines` 不重排、不去重；拒绝提示的「先接取 → 再拒绝 → 最后已完成」由内容侧保序 |

## 不变量（门禁逐条钉住）

* **构造 O(1)、零遍历**：`QuestLog` / `Objectives` / `Quest` 构造期只校验注入面 + 存引用，
  不读账本 / 目标 / 注册表数据，不建索引（门禁用探针对象 + 10^5 次构造成本对照钉住）。
* **不可变**：迁移返回新 mapping；未改动的嵌套对象按浅拷贝共享（不做深拷、不写回原 raw）。
* **异常不吞**：四个目标回调与注入策略抛出的异常**原样上抛**。
* **顺序即语义**：注册声明序 = `keys()` = `hits()`；目标键序 = `parts()` = `lines()`；
  `snapshot()` 键名与键序逐字保留；`archive` 追加**不去重**。
* **只有标准库 + 相对导入**：不 import 内容侧任何模块；不 import `os`/`sys`/`json`/
  `datetime`/`time`/`calendar`/`random`（不落库、不读钟、不读环境）。
* **零取值**：引擎源码的**代码路径**字符串常量里没有任何游戏取值词（`ast` 静态扫描钉住）。

## 已知边界（诚实列出）

* **不落库**：`snapshot()` 只回写成原形态的浅拷贝；键怎么拼、JSON 怎么写全在内容侧。
* **不认状态词 / 目标类型词 / 字段名**：全部注入；引擎角色键只是它自己那套结构名。
* **不做跨天清理**：每日刷新与系统钟口径逐字保留在内容侧（分歧⑪是**缺口**不是设计）。
* **不做门槛与列表过滤**：可接清单的过滤集合、短路序、拒绝提示行序都是内容侧的信息设计。
* **不做悬空链校验**：`next` 悬空、解锁闭环是导出器职责；读路径不做全表扫描。
* **`satisfied` 的进度键口径只有一个**：目标值。内容侧若用别的进度键（聚合键等），
  由内容侧自己判定（引擎不猜键、不翻译），这是分歧⑦的机械后果。

## 门禁

`tests/test_quest_shape.py`（244 断言，单文件自跑，不依赖 pytest）：
目标注册表逐条（声明序 / 修饰键归属 / 需求数 / 命中 / 折叠 / 达成 / 行文 / `unknown`）·
账本读口与六个迁移逐条 + **每条兜底分支各一断言** · 不变量（构造零遍历 / 注入面 fail-closed /
迁移返回新对象 / 不改原 raw 的 `json.dumps` 指纹 / 不缓存 / 异常不吞 / 顺序断言）·
**12 条口径分歧各 ≥1 断言**（故意不同的两口径断言「确实不同」）·
**有牙反证**（逐处打印「预期变红 / 实测变红」+ 两处同坏 + 第三处仍绿）·
**零知识静态扫描**（`ast` 扫代码字符串常量取词 + import 白名单）· 构造 10^5 次。

引擎侧另有两条既有的全仓门禁把关：`tests/test_engine_purity.py`（只相对导入 + 标准库）
与 `tests/test_no_game_vocabulary.py`（零游戏身份词）。
