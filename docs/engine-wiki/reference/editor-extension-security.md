# 编辑器扩展面 · 为什么不执行包提供的代码

> **决策页**：写清**为什么**编辑器扩展面不跑包提供的代码（含**为什么不让包的 JS 进页面**），
> 以及**将来若要支持**该怎么设计、什么条件下才允许开。
> 适用范围：框架编辑器（`editor/`）的**包扩展面** —— 包能在自己目录里放什么、编辑器拿它做什么。
>
> 一句话结论：**包的「声明」可以进编辑器，包的「代码」不进。**
> 渲染 / 编辑链路只读包交的 JSON；包的 Python 与 JS 都不在这条链路上执行。
> 包代码唯一被允许跑的地方是**一次性子进程**（「试跑 / 试玩」两个按钮），不是渲染链路。

---

## 0 先分清两条路：游戏路 vs 编辑器路

| 路 | 谁在跑 | 跑包代码吗 | 为什么 |
|---|---|---|---|
| **游戏路** | 引擎 + 包（`content/apply.py`、`content/mech/*.py`） | **必须跑** | 包**就是**这个游戏：机制、指令、脚本的真源就是这些 Python 文件；不跑 = 这个游戏不存在 |
| **编辑器路** | `editor/`（造包 / 改包的工具） | **不跑** | 编辑器是**工具**，会用来打开**别人的包**；「打开」若等于「执行陌生人的代码」，风险面是白送的 |

**关键推理（本页的轴）**：从「游戏路径必须跑包代码」**推不出**「编辑器路径也要跑包代码」。
两条路的信任模型相反 —— 游戏路把包当**自己的游戏**（用户主动要跑它），
编辑器路把包当**不可信输入**（用户只是想看看 / 改改它）；混在一条链路上，
等于让「打开一个包」顺带带上「运行一个包」的后果。
编辑器当然也保留了跑包代码的能力（试跑 / 试玩），但它们在**子进程**里、由用户**显式点击**触发（§2.f）——
本页要守的界线是：**别把这条能力接到渲染 / 编辑这条常驻链路上。**

## 1 三层扩展面：包交什么 / 跑不跑包代码

「层」是包**能声明什么**的阶梯；「跑不跑代码」是**信任档**。核心决策一句话：**表达力可以往上加，信任档不动。**

| 层 | 包侧交什么 | 编辑器拿它做什么 | 跑包代码吗 | 现状（2026-09-14 核代码） |
|---|---|---|---|---|
| **层 1 · 数据扩展** | `editor/domains.json` + `schemas/<域>.schema.json` + `content/{data,rules}/<域>.json` | 域注册表 / schema 校验 / 表单 / 条目读写 | **不跑** | ✅ 已落地 |
| **层 2 · 半动态声明** | `editor/relations.json`（字段↔域引用、联动 / 只读）+ `editor/views.json`（域 → **内置**视图名） | 引用下拉与引用校验；把域接到 5 个**内置**视图之一 | **不跑** | ✅ 已落地（视图白名单见 `relations.py:75`） |
| **层 3 批 1 · 渲染声明（纯声明）** | `editor/render/<域>.json`（版面 / 字段 / 条件 / 插值） | 声明 → **受限渲染树（JSON）** → 前端白名单渲染器画 | **不跑** | ✅ **已落地**（`editor/render.py` + `render_decl.py`） |
| **层 3 批 2 · 白名单派生值** | 声明里只**点名**框架的白名单纯函数（`DERIVE_FNS`），包不提供函数体 | 值由沙箱子进程算（跑的是**框架**代码） | **不跑包代码** | ✅ **已落地**（`editor/render_worker.py` 沙箱子进程） |
| **层 3 批 3 · 代码档** | 包自己的渲染代码（`editor/render/<域>.py` 里的 `derive()`） | 在**沙箱子进程**里跑它，只回受限渲染树 | **跑包代码** | ⛔ **当前决定：不做**（声明面已能识别它并标红） |
| **前端 JS** | ——（包**不往页面塞任何 JS**） | 编辑器自己的手写前端：第 5 档 + 白名单渲染器 | —— | ✅ 已落地；树的文本一律 `textContent`（`web/app.js` 有明注） |

> **现状怎么核（2026-09-14 复核）**：层 3 **批 1（纯声明）已落地** —— `editor/render.py` / `editor/render_decl.py`
> + `GET /api/package/<id>/render`（`server.py:428`）+ 前端第 5 档 + 三门禁；它**不执行任何包代码**
> （批 1 那两个文件里 `subprocess` / `eval(` / `exec(` 计数 = 0）、也零引擎 import（见 §4 第 4 条）。
> **批 2（白名单派生值）也已落地**：`editor/render_worker.py`（875 行）的沙箱子进程 —— 一次性 /
> import 白名单 / 超时 / 输出上限，跑的是**框架**白名单纯函数，**不跑包代码**；起进程的调用只在
> `render_worker.py` 里，父侧 `render.py` 惰性 import 它。批 3（代码档）**仍为不做**；iframe（路径 B）
> 也没有代码。`editor/README.md` 的第 3 层表格已同步（分「批 1 / 批 2」两行）。

### 1.1 包侧文件落点（层 1 → 层 3）

```text
<pkg>/
  game.json                       包清单（id / 名称 / 引擎版本要求）
  editor/
    domains.json                  层 1：域声明（kind 决定落 content/data 还是 content/rules）
    relations.json                层 2：字段↔域引用 + 联动 / 只读
    views.json                    层 2：域 → 内置视图名（5 个白名单之一）
    glossary/<域>.json            第 2/3 层之间：字段词典（中文名 / 注脚 / wiki 深链）
    render/<域>.json              ★ 层 3 批 1（**已落地**）：版面 / 字段 / 条件 / 插值（纯声明）
    render/<域>.py                层 3 批 3（**决定不做**）：包的 derive() 代码档（声明面只做存在性识别）
    render/<域>.html.js           路径 B（默认关，**无代码**）：iframe 只读预览用的包 JS
  schemas/<域>.schema.json        层 1：该域的 JSON Schema（不给 = 该域不校验）
  content/{data,rules}/<域>.json  层 1：数据本身（编辑器读写的就是它）
```

> `render/` 与 `glossary/` 都在**包内**、都随导出 zip 走（§2.c）—— 「包自己的 `editor/` 目录」
> 是扩展面的统一落点，不是框架的目录。

### 1.2 为什么"声明"是安全的

* **声明是数据**：JSON 解析 + 形状校验 + 白名单枚举；坏了只「忽略该项 + 一条可读告警」，绝不 500。
* **声明无法指定"执行什么"**：`views.json` 只能点名 5 个**内置**视图名（`relations.py:75` 的 `VIEW_NAMES`）——
  第 2 层落地时就把「包不写新代码」写成硬口径；层 3 批 1/2 延续它：派生只点名**框架的白名单纯函数**。
* **声明里塞不进"一段代码当字符串"**：协议里没有任何执行入口；字符串只当文本、前端**转义后**渲染
  （层 3 批 1 的规则「树 ≠ HTML」就是为此立的，见 §3 路径 A 的"回程协议"）。

## 2 为什么不做（把理由写透）

### a) 编辑 / 渲染路径与"游戏路径"是两条路

编辑器路径是**工具**，主要用途恰恰是**打开别人的包**（导入入口 `POST /api/packages/import` 收的就是陌生 zip）。
现有导入闸（`editor/dist.py` 的四道）拦的是 zip slip / zip bomb / 清单合规 / 引擎版本，**不拦"包里带代码"** ——
这是有意的：包本来就该带代码（`content/apply.py`、`content/mech/*.py`）。但「包里带代码」与
「编辑器替它跑起来」是两件事：渲染一旦能跑包代码，「打开一个包」就从「读数据」升级成「执行代码」，
而这一步没有任何用户可见的收益。

### b) 同源写权限：页面里的 JS 能直接改磁盘文件

编辑器主页面与 API **同源**（同一个 `http.server`，只绑 `127.0.0.1`，见 `editor/server.py:50` 的自述）。
页面 JS 只要发一条 `PUT /api/package/<id>/d/<dom>/<key>` 就能改盘上的包文件：

* 前端拼路径与发请求：`web/app.js` 的 `dPath`（`:204`）、保存（`:1416` / `:1476`）；
* 服务端：`server.py:705-721`（`_mutate` 的 PUT 分支）先跑 schema + 引用校验，过了再调
  `PK.put_entry`（`packages.py:665`）→ `write_json`（`packages.py:392`）落盘；`_mutate` 里**没有** Origin / CSRF 校验。

⇒ **包的 JS 一旦进页面，等于把「写盘」这项能力交给包**：它不需要攻击编辑器进程，只要用页面的身份发请求
就能改数据、导出整包、再导入别的包（`web/app.js:463` 导出 / `:491` 导入）。同源是浏览器里唯一真正有效的
信任边界；为了让包自定义渲染而破它，代价远大于收益。

### c) 供应链：包内的 `editor/` 会随 zip 传播给第三方

导出走 `os.walk` 收包内全部文件，`_SKIP_DIRS`（`dist.py:48`）只跳缓存 / 依赖 / 版本控制目录，**不含 `editor/`**；
`_iter_files`（`dist.py:55`）因此把包自己的 `editor/**` 一并打进 zip（`editor/README.md` 也明说导出
「含包自带 `editor/`、`schemas/`」）。⇒ 今天看着「只是本地声明」的东西，明天会出现在第三方机器上 ——
所以扩展面从第一天就得按**不可信输入**对待，不能靠「只有我自己写包」。

### d) Windows 现实：我们的"沙箱"只是**隔离 + 限额**，不是内核级隔离

全仓检索不到 `resource.setrlimit`（Windows 上没有这个 API），也没有 `pywin32` / `ctypes` 写的 Job Object
之类 OS 级隔离代码（2026-09-14 实测：零命中）。所以即便走 §3 路径 A 的沙箱子进程，能**保证**的只有：
进程边界 + 墙钟超时 + import / 内置函数白名单 + 空工作目录 + 输出上限 + 渲染不写盘。
**不能**保证一个**精心构造**的 Python 包找不到逃逸路径 —— CPython 的对象图反射
（`object.__subclasses__()` / `getattr` 链 / 经 builtins 找回 `__import__` …）是公开的逃逸面。
⇒ 必须如实写成「**尽力拦截 + 已知残留清单**」，**不许包装成"安全沙箱"**；这条也支撑了默认档的选择：
**唯一稳的安全措施是不执行。**

### e) 收益 vs 成本：现有的包没有一个需要它

现装包：`games/orlandia`（`editor/domains.json` 声明 **73** 个域、`editor/glossary/` 70 份）、
`examples/minimal-game`、`games/my_game`（新建包脚手架）。核对结果：**没有一个**声明 `views.json`
或 render 面，更没有包要求跑自己的渲染代码。层 2 已覆盖「引用 / 联动 / 换内置视图」，
层 3 批 1/2（纯声明 + 白名单函数）已落地、**批 3 代码档**仍不做；在**没有任何真实需求**时先开「代码档」，
等于为一个锦上添花的能力长期背安全债。

### f) 编辑器**已有**两处故意执行包代码的地方 —— 都在子进程，都不是渲染

1. **试跑**：`POST /api/package/<id>/simulate` → `editor/simulate.py` 起 `simulate_worker.py`，
   子进程里 `pkg_loader.load(pkg_dir)`（跑包的 `content/apply.py` + 引擎）跑一场最小战斗；
   父进程侧唯一一次起进程在 `simulate.py:30`。
2. **试玩**：`POST /api/package/<id>/play`（`routes_play.py:81` 的 `_mutate` 分支）→ `editor/play.py`
   起 `play_worker.py`，子进程里 `import game` + `load_package` 走真实游戏那条路；父进程侧起进程在 `play.py:74`。

两处共同点：**用户显式点击**、**一次性子进程**、超时掐死、父进程零引擎 import。
本页说的是「要不要为**渲染**再开第三处，而且是在页面里」—— 答案是不开。

## 3 将来若要支持，怎么设计

两条路径分开写。**共同前提**：回程只能是**受限渲染树（JSON）**，协议里**没有 `html` 字段** ——
回程一旦是 HTML，就等于我们要自己写一个 sanitizer，那是无限的 CVE 面。
**现状**：路径 A 的**批 1（纯声明 → 树 → 前端白名单渲染）已按下面这套边界落地**；`$allow_code`
开关已进声明 schema（`render_decl.py:75`），但**当前只被读取并上报，没有任何执行路径**。

### 路径 A：Python 代码档（渲染派生）——主执行面

* **落点与隔离**：包内的独立文件 `<pkg>/editor/render/<域>.py` → **子进程**执行。
  **进程即隔离边界**：父进程按墙钟杀进程；一次性进程、不驻留（常驻 = 状态泄漏面 + 生命周期复杂）。
* **限制**（实现即照做）：白名单 `builtins`（去掉 `open` / `eval` / `exec` / `compile` / `__import__` /
  `getattr` / `setattr` …）+ import 白名单（`json` / `re` / `math` / `decimal` / `datetime` /
  `collections` / `itertools` / `functools` / `statistics` / `textwrap`）+ 墙钟超时（父侧，缺省 1500ms）
  + 输出上限（1MB）。**内存上限**是另一个手段问题：Windows 无 `rlimit`，只能考虑 `ctypes` 调 Job Object ——
  标为实现期决策；若不做就明确写「内存不设硬上限，靠超时 + 输出上限兜」。
* **能力收窄清单**（照此实现，别自由发挥）：

  | 收窄项 | 手段 |
  |---|---|
  | import 面 | `sys.meta_path` 插 finder，只放行 stdlib 白名单；其余一律 `ImportError`；**拒绝**包根 / 引擎根进 `sys.path` |
  | 内置函数 | `__builtins__` 换白名单 dict；去掉 `open` / `eval` / `exec` / `compile` / `__import__` / `globals` / `locals` / `getattr` / `setattr` |
  | 文件系统 | 工作目录 = **空临时目录**；`open` 不在白名单 → 打不开任何文件；不把包目录设成 `cwd` |
  | 网络 / 进程 / 线程 | 都不 import（白名单外）：`socket` / `urllib` / `http` / `ssl` / `subprocess` / `threading` / `multiprocessing` / `asyncio` / `os` |
  | 反射逃逸 | 不 import `inspect` / `ctypes` / `importlib`；**注意**：`object.__subclasses__()` 这类经典逃逸在纯 Python 里堵不死（§2.d） |
  | 输出与数据 | 只认 stdout 的 marker 行，其它丢弃；只给**该条目**的数据 + 该域词典 / schema 摘要（不给全包、不给别的域） |

* **协议**：抄既有两个子进程先例的形状 —— 父 → 子：`stdin` 一个 JSON（包目录 / 域 / 条目 / 数据 / 声明 / 限额）；
  子 → 父：`stdout` 每行 marker + JSON，末行一个 summary（`done` / `decl` / `limit` / `timeout` / `crash`）；
  父进程**校验回程树 + 限额截断**。
* **开关**：**默认关**。开启 = ① 包**显式请求**（如 `"$allow_code": true`）**且** ② 用户**首次显式确认**
  （选择记 `sessionStorage`，**不落包**）；关掉时「零代码执行」必须**可断言**（与纯声明档逐项一致）。
* **回程协议**：**只回受限渲染树 JSON**，字段全在框架白名单里；未知键**丢弃**、超限**截断**、
  数字 / 字符串按上限封顶；**协议里没有 `html` 字段**。
* **前端**：必须用框架自己的**白名单渲染器**画树（块类型枚举 → 固定组件），**不许 `innerHTML` 直插**包给的文本；
  唯一允许的富文本是三个行内标记（`**粗**` / `*斜*` / `` `等宽` ``），由前端 `createElement` 生成。
* **诚实残留**：已知逃逸手法（`object.__subclasses__`、`getattr` 链、经 builtins 找回 `__import__` …）
  只能**尽力拦截**；必须把残留**列成清单**随实现一起发布，**不许声称 100%**（理由见 §2.d）。
* **门禁**（三件齐备才算落地）：逃逸尝试用例（`open()` / `import urllib` / `import os`）+ 超时 / 崩溃 /
  巨输出用例 + 「开关关时零代码执行」可断言 + 父进程零引擎 import 的硬断言。
* **风险标注**：编辑器的**导入 / 打开**流程若遇到这类包，要**显式提示**「该包请求执行代码」，不许静默加载。

### 路径 B：前端 iframe（把包的 JS 关进沙箱）——只做默认关的只读预览

* **方向**：只做**默认关的只读预览**（收益最小：主要覆盖画布类可视化，如拓扑 / 曲线 / 拖拽地图）。
  它给不了"编辑"—— 编辑要回写，回写就要信任，信任又回到路径 A 的校验链。
* **属性**：`<iframe sandbox="allow-scripts" srcdoc="…">`，**不给** `allow-same-origin`、不给 `allow-forms`、
  不给 `allow-popups`、不给 `allow-top-navigation`；另加 CSP `default-src 'none'; style-src 'unsafe-inline';
  script-src 'unsafe-inline'`。
* **回程**：iframe 里只收到该条目的**只读 JSON 快照**（`postMessage` 定向 origin）；回程**只有**
  `{type:"render_ok"}` / `{type:"render_error"}` 之类消息 —— **页面不接受包给的 HTML / JS**；
  要写回只能提交「候选补丁」，由父页面按既有校验链校验后才允许应用。
* **落地前必须先做浏览器矩阵小样验证**：各浏览器对 `sandbox` + CSP（尤其 `srcdoc` 下的
  `<meta http-equiv>`）的组合行为不一致，没实测过不许写进实现。

### 已否决的路径（写明否决理由，避免后人重走）

* **自写"受限 JS 解释器"**：数千行新代码 + 无限 CVE 面；且直接破坏编辑器后端「零第三方依赖、只用 stdlib」
  这条既有纪律（`editor/server.py` 是 `http.server` 手写服务）。
* **引第三方 JS 沙箱库**：同样破纪律（编辑器前端是**无构建步骤**的手写文件）；而且表达力上限并不比路径 A 高 ——
  路径 A 的树 + 白名单派生已覆盖「版面 / 派生 / 受控交互」三类真实诉求，多引一个库只换来更多供应链面。

### 共同要求：降级链（永不白屏）

| 档 | 触发 | 用户看到 |
|---|---|---|
| **L0** | 无 render 声明 | 走既有第 2 层（`views.json` / 内置默认）→ 都没有就普通表单 |
| **L1** | 声明**坏了**（坏 JSON / 未知块 / 形状不对） | 第 2 层 + 顶部黄条（可读告警） |
| **L2** | 声明好、但树里某块不合规 | 只降级**那一块** + warning，**不整域放弃** |
| **L3** | **渲染期失败**（超时 / 崩溃 / 输出超限 / 非零退出） | **整域**回退第 2 层 + 黄条（带 stage）+「重试」 |
| **L4** | 前端**应用树时**抛异常 | 该域**本次会话**禁用 render → 退回表单 + toast |

三条硬要求（写进验收）：① 任一档都**必须**仍有可用编辑面 —— **JSON 档永不可禁用**；
② 降级必须**可见**（黄条 / toast），**不许静默**；③ 降级状态下**保存 / 删除照常可用**。

## 4 什么条件下可以开启（红线）

四条**同时**成立才允许开工；缺一条就不开：

1. **有真实的包需求** —— 是某个包**真的**卡住了（而不是"可能有人需要"）。§2.e 的现状是「零需求」，
   这条不过，后面三条都不用谈。
2. **路径 A/B 的沙箱实现 + 逃逸残留清单 + 门禁三件齐备并已落地** —— 缺一不可。
3. **「默认关」+「用户显式确认」两个开关不得取消** —— 不许因为"包作者嫌麻烦"就改成默认开，
   也不许把确认弹窗做成可永久跳过。
4. **编辑器链路的「零引擎 import」硬门禁不得破** —— 既有口径是：干净解释器里 `import editor.play`
   之后 `sys.modules` 不许出现 `saintess_engine*`（`tests/test_editor_play.py:127` 的 `test_zero_engine_import`），
   反证是**子进程侧**才许 import 引擎；**层 3 批 1 已加同款断言**（`tests/test_editor_layer3_render_decl.py` 的硬断言段：AST 不 import 引擎、`import editor.render` 后 `sys.modules` 零 `saintess_engine*`）。
   ⚠️ 口径注意：说的是**试跑 / 试玩 / 渲染这些链路自身**，不是"整个 `server.py` 进程" ——
   `server.py:71` 经 `editor/packages.py` 的 `install_engine`（`packages.py:537`）本来就会碰到引擎装配。

## 5 常见误解（写下来省一次争论）

1. **「引擎和游戏都能跑包代码，编辑器为什么不能？」** —— 信任模型相反（§0）：游戏路的包是"用户主动要跑的
   游戏"，编辑器路的包是"别人递来的输入"。
2. **「那把渲染限制成只读不就安全了？」** —— 只读 ≠ 安全：主页面同源，包的 JS 即使"只渲染"也能读全包数据、
   并发 `PUT` 写盘（§2.b）。真正隔断同源的是 iframe（路径 B），而它的收益最小。
3. **「只跑包里的纯函数、不碰 IO，总没事吧？」** —— 纯函数仍然是 Python：逃逸面在语言层，
   不是"有没有写 `open`"（§2.d 与路径 A 的"诚实残留"）。
4. **「默认关 + 弹窗确认一下就行了吧？」** —— 开关是**必要**条件不是**充分**条件：真实需求、残留清单、
   门禁三件同样要齐（§4）。
5. **「层 3 不是已经做了吗？」** —— 做了**批 1（纯声明）与批 2（白名单派生值，沙箱子进程）**；
   批 3（代码档）**当前决定不做**，iframe 也没有代码（§1 现状）。反向的坑也要防：
   `editor/README.md` 那张表此前一直滞后，现已按实际状态更新（第 3 层分「批 1 / 批 2」两行）。
6. **「包 JS 只在 iframe 里跑，就等于隔离了。」** —— `sandbox` 省略 `allow-same-origin` 只是"不能读父页面 /
   不能带 cookie 调同源 API"，**不是绝对隔离**；所以路径 B 只能是「只读展示 + 默认关」。
