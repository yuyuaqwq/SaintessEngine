# 对话树形状（节点 / 选项 / 条件槽 / 会话游标）

> 模块：`ext_dialogue.dialogue` —— `Dialogue`（树读取 + 条件槽 + 渲染槽 + 选项路由）
> + `Cursor`（会话游标**值**）+ `END_KEY`（注入面**字段名**）。
> 一句话：**一棵「跟谁说话 → 说哪句 → 给哪些选项 → 选了去哪」的树**；
> 节点 id、台词、条件、动作、结束哨兵全部由内容侧给，引擎只认**字段名**与**注入口**。

## 为什么有它

参考实现里，对话被读成好几份形状 —— 取节点、过滤可见选项、按条件择优挑台词、
把选项路由到下一节点、把「当前聊到哪」写进存档再读回来。这些读法分散在
「纯逻辑模块」与「命令层装配」两侧，各写各的兜底分支（未知节点怎么办、展开为空怎么办、
失败转怎么走）。把「哪个主体 / 哪句台词 / 什么条件 / 什么动作」这些**取值**拿掉，
剩下的五件事就是形状：

| 形状 | 一件什么事 | 谁给 |
|---|---|---|
| 树 | `nodes` 按 id 取节点；未知 id **回退 `start`** | 内容侧数据 |
| 条件槽 | 节点/选项上挂 `need`，逐键问注入的谓词查表口 | 谓词实现与条件名全在内容侧 |
| 渲染槽 | `text` / `texts`（条件变体）/ `text_from`（注入的自动文本源） | 台词与生成器全在内容侧 |
| 路由 | 选项 `next` / `fail_next` → 下一节点 id | 节点 id 与失败转由数据给 |
| 游标 | 「跟谁 + 在哪」两个不透明字符串 | 字段名与存储键由调用方给 |

## 用法

```python
from ext_dialogue.dialogue import END_KEY, Cursor, Dialogue

# ① 一份注入面（引擎零默认值：结束哨兵 / 兜底文案 / 谓词查表口 / 未注册键策略都必填）
cfg = Dialogue(
    end_marker=<结束哨兵>,                 # 取值：数据约定
    fallback_text=<兜底文案>,               # 取值：文案
    conditions=<有 get(key) 的查表口>,       # 鸭子类型：引擎不 import 它，也不改它的签名
    unknown=<未注册 need 键的策略>,          # unknown(key, value) -> bool（真 = 放行；可抛）
    text_sources={<取值>: <fn(node, ctx)>},  # 可选；None = 没有自动文本源
)

# ② 一棵树 = 一个新外壳（O(1)：只换引用，不遍历、不缓存）
dlg = cfg.of(tree)

node = dlg.node(dlg.start)                     # 命中就用它；未知 id 静默回退 start
opts = dlg.options(node, ctx, expand=expand_fn)  # 声明序；side_menu 就地展开
line = dlg.text(node, ctx)                       # 变体 → 自动源 → text → 兜底
opt  = dlg.pick(node, 1, ctx, expand=expand_fn)  # 1-based；越界 → None（不抛）
nxt  = dlg.next_of(opt, failed=action_failed)    # next / fail_next / end_marker
if dlg.is_end(nxt):
    ...                                          # 结束；会话怎么清由调用方决定

# ③ 会话游标：值进引擎，存储不进（存档键与 JSON 文本一字不动）
cur = Cursor.of(raw, subject_key=<键名>, node_key=<键名>)   # 读不出来 → None（不抛）
raw = cur.moved_to(nid2).state(subject_key=<键名>, node_key=<键名>)   # moved_to 返回新对象
```

## 引擎认什么（契约字段名）

引擎把调用方的原始 mapping **原样持有** —— 不归一、不拷贝、不补默认值，只按下列字段名读：

| 层 | 字段 | 边界（有意保留的口径） |
|---|---|---|
| 树 | `start` / `nodes` | 缺失 → `{}`；`nodes` 的值可以是任意对象（含 `None`）→ 原样返回 |
| 节点 | `text` | 缺失 → 注入的 `fallback_text` |
| | `texts` | `[{need, text}]`，**声明序 = 优先级**；变体缺 `text` 键 → `KeyError`（不兜底） |
| | `text_from` | 取值是注入表的键；不在表内 → 跳过，不调用任何生成器 |
| | `options` | 缺失 / 空 → `[]` |
| 选项 | `text` | **引擎不读**（渲染留调用方） |
| | `next` / `fail_next` | 缺失 → 结束哨兵；`fail_next` **存在但假值 → 就用它**（不回落） |
| | `need` | 缺失 / 假值 → 不限；`{键: 值}` 逐键**与**、按插入序短路 |
| | `action` | **完全不透明**，只做「原样带出」 |
| | `side_menu` | `is not None` → 走动态展开分支（空的 `{}` 也算） |
| ctx | 任意 | 引擎一个字段都不读，只整体透传给注入的谓词 / 文本源 |

> 上面出现的都是**字段名**（引擎契约词汇）；一切**取值**（结束哨兵、兜底文案、自动文本源的
> 键、条件名、动作载荷）由注入面给。引擎源码的字符串常量里没有任何一个取值 —— 门禁用
> `ast` 扫源码常量把这条钉死（判据只针对**代码路径**；docstring 是散文，不参与扫描）。

## 规则要点（细节见模块 docstring 的十条口径分歧）

* **`need`**：假值 = 不限；否则逐键**与**、短路（首个不满足即停，后续谓词一次都不调用）；
  未注册键交给注入的 `unknown`；谓词结果按**真值**判定（`None` / `0` 都算不满足）；抛错原样上抛。
* **`options`**：声明序输出；`side_menu` 项先过 `need` 再展开，展开结果**插回原位置**，
  展开空 / 未注入回调 → 整项消失；普通项返回**原对象**（`is` 相同）。
* **`text`**：变体按声明序取**第一个满足者** → 注入的自动源（返回真值才用）→ `text` → 兜底。
* **`pick` / `next_of`**：`pick` 是 1-based，越界 → `None`（`0` 的「结束」语义在调用方）；
  `next_of(failed=True)` 优先 `fail_next`。动作路由的 token 引擎**不认识**，调用方把动作
  结果翻成一个 `bool` 传进来。

## 与其它形状的分工

| 相邻能力 | 归谁 | 说明 |
|---|---|---|
| 网状连通 / 深度 / 出入口 | [space.md](space.md) | 对话树是「显式选项边 + 每条边带载荷与谓词」，遍历靠玩家选择，不是拓扑派生 |
| 线性进度（声明序下一站） | [run.md](run.md) | 对话是**图**且跳转任意；`Progress` 是可变的线性有序进度，语义不重合 |
| 输入 → 指令（裸数字、结束词、越界文案） | `command` | 选项路由只做「选项 → 下一节点」，输入解析在命令层 |
| 键 → 模板 + 参数填充 | `text` | 对话台词是「按条件择优 + 可选自动生成」，形状不同 |
| 条件注册与查表 | `conditions` | 这里只借它的 `get(key)` 查表口（鸭子类型）；它已有的是**单参**求值，本形状要的是**两参**谓词 |

## 已知边界（诚实列出）

* **不落盘、不缓存**：`Cursor` 只是**值**；存档键与 JSON 文本由内容侧拼与写（本形状一字节不动）。
* **游标不持上下文**：判定用的上下文每步现场取。把上下文塞进游标 = 把一份过期世界冻进存档。
* **不做全树校验**：悬空 `next`、`start` 缺失、未注册 `need` 键的构建期扫描是导出器的活；
  读路径不做全树扫描（构造零遍历）。
* **异常不吞**：谓词 / 文本源 / 展开回调抛出的异常原样上抛 —— 与「自己写 if 链」一致。
* **渲染不在引擎**：序号行、头衔、图标、提示语、结束项全是内容侧文案。

## 门禁

`tests/test_dialogue_shape.py`（159 断言，单文件自跑，不依赖 pytest）：
规则逐条（R-NEED / R-OPT / R-TEXT / R-ROUTE）与**每一条兜底分支各一断言** ·
不变量（构造零遍历 / 不缓存 / 不可变 / 注入面 fail-closed / 异常不吞 / 对象标识 / 幂等）·
**零知识静态扫描**（`ast` 扫源码常量取词 + import 白名单）· 十条口径分歧（**故意不同的两口径
断言「确实不同」**）· 多故障场景（两处同时坏 + 第三处仍绿）与顺序断言 · 纯 JSON 视图。

引擎侧另有两条既有的全仓门禁把关：`tests/test_engine_purity.py`（只相对导入 + 标准库）
与 `tests/test_no_game_vocabulary.py`（零游戏身份词）。
